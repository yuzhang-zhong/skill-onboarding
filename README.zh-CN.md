## 装了一堆 skill，常用的就那一个

skill 不会一次全读进来。会话刚开始，只有名字和一句描述进到上下文里，正文要等真正用上才读。所以一个 skill 就算写了八个功能，你也只会碰上最前面两个，另外六个一直藏着。

这个 skill 就补这一个缺口。你第一次真正用上某个 skill 之后，它会跑一遍真实验证，把全文读完，给你一张卡，上面写的是你没发现的那部分。

## 三步

1. **定对象** 一个 skill，还是一组
2. **探测** 读全文，跑只读探针。真跑，不猜
3. **出卡** 一张能一口气读完的卡

## 一组 skill，其实是同一件事

同一个工具，常被拆成十几个 skill 分开装。也有反过来的时候，一个 skill 里塞了五十个命令。

拆开装，你手里就有十几张脸，却拼不出这一个东西的全貌。闷在一个文件里，你只会记得最顺手的那一条。两种都吃亏。所以合并成一张卡。

顺手算个差集：这个工具本身支持的，减掉你本地已经封装的。差出来的，就是你完全不知道的那些。

## 三个真实案例

下面三张卡是实际跑出来的，不是示意。原文照贴。

### 一、你天天在用编程助手，只用了它两件事

改代码、跑命令。就这些。它还能挂后台、开子智能体、自动压缩上下文、配钩子。你从来没碰过，因为描述里没写。

跑一遍，拿到这个：

```
✅ 可用。核心能力全部实测通过，上下文压缩、子智能体、记忆文件、钩子都能正常工作。

你手上这个编程助手本体。多数人只用到两件事：改代码、跑命令。剩下的能挂后台跑、能开子智能体并行干活、能自动压缩上下文、能配置在特定时机自动触发脚本，很少有人碰。

能干什么

    改代码、跑命令        基础操作，你天天在用
    挂后台跑长任务        编译、装依赖、跑测试不用干等，跑完自动通知
    开子智能体并行干活    多个方向同时推进，各自独立探索，不挤占主上下文
    自动压缩上下文        快到上限时自己整理，长会话不会断
    写记忆文件            把项目约定和你的偏好落盘，下次开新会话自动带上
    配钩子                在指定时机自动跑脚本，比如提交前检查、改完自动格式化

几个多半不知道的

    这个任务你后台跑，跑完告诉我    长命令不用守着，完工自动回来汇报
    派三个方向同时查一下            并行探索，比排队一个个来快得多
    把这条约定记到项目里            写进记忆文件，以后不用反复交代
    这个项目用什么规范捋一遍        读记忆文件和配置文件，一次说清当前项目的约定
    每次改完自动跑一遍测试          钩子机制，把重复动作固化下来
    上下文快满了，整理一下          手动触发压缩，不用等它自己动手

记不住就存这句

    这个先挂后台跑，完了叫我
```

最后那条最值钱。命令在跑，人可以走开。

### 二、PDF 技能你只当它是个朗读器

你用它读过文字、转过图片。然后呢？没了。你以为它的能力就是"读"，所以做表格、填表单、涂黑这些事你想都没往那儿想。

跑一遍，拿到这个：

```
⚠️ 部分可用。核心命令实测正常，50 个命令全部注册成功。OCR 和格式转换要另外装系统工具，本次没装。

处理 PDF 的一站式工具。50 个命令分六类：读、改、转、表单、加密、结构。你以为它只会读文字，其实能改扫描件、填表单、涂黑脱敏、给两个版本做差异对比。

能干什么

    读            提文字、提表格、提图、提公式、看布局、看阅读顺序
    改            换字、加字、删字、换图，支持只落文字层的和纯扫描件两种
    转            和 Word / HTML / Markdown / 图片来回转，压缩、拆分、合并、裁剪、旋转
    表单          识别字段、填字段、没字段的也能按坐标填、填完拍平
    加密          加密码、去密码、涂黑脱敏、盖签名章
    结构          导出成 JSON 看清全貌、改完再重建、两个版本比差异

几个多半不知道的

    这张纸是扫描件还是电子件    一条命令逐页判断，后面该走哪条路就不用猜了
    把这几页拼成一张长图        定高截图、朋友圈长图、聊天记录归档都能用
    文档切块喂给 AI            四种切法，段落、页、定长、语义，专门为知识库准备的
    身份证号给我涂掉            支持按文字、按区域、按正则三种方式涂黑，连底下的文字层一起清
    这两个版本的合同差在哪      直接对比两个 PDF 的结构和文字，出差异清单
    填好的表单别让人再改        一次拍平，字段和注释都固化成页面内容

记不住就存这句

    这个 PDF 帮我处理一下，先看看是电子件还是扫描件
```

第二行就摆着 50 个命令。第一条差集让你先分类型再动手，这条路很多人走反了。

### 三、选股工具你只用了一种筛法

你知道它能"帮我找几只股票"。于是你只会写条件。策略、标签、事件、排行四套入口，加几百个现成分类，一直躺在那儿。

跑一遍，拿到这个：

```
⚠️ 部分可用。六种查询入口实测正常，`--list` 系列都能真实返回清单。没配行情服务的环境下，结果需要另接数据源。

按条件从全市场挑股票和基金的工具。你以为它只是"帮我找几只股票"，其实它有六种找法，每种的参数规模都在几百到上千条，绝大多数人只知道其中一种。

能干什么

    按条件筛         写表达式，比如市盈率小于 20 且净资产收益率大于 15
    按策略筛         现成的信号，金叉、超卖、大师策略、K 线形态，报个名字就行
    按标签筛         央企、破净、次新、千元股，几百个现成分类
    按事件筛         近期解禁的、正在回购的、要进指数的，几十种事件
    按指标排行       评分榜、涨跌停榜、两融榜、资金流入榜，还能先圈定范围再排
    挑基金           同样的两套入口，换成 ETF 就是主题池和规模榜

几个多半不知道的

    央企里评分最高的十只          先圈定范围再排序，这是它最顺手的能力，很少人知道
    金叉里估值最低的              策略结果内二次排序，不用自己导出来再筛
    最近有哪些股票要解禁          按事件找股票池，不是按日期翻日历，两回事
    两融连续加仓五天以上          阈值筛选，不是取前多少条，业务含义完全不同
    估值在历史什么位置            基金有历史百分位排行，比看绝对值有用
    换个日期看看上周什么情况      支持指定历史日期，也能给区间看名单变化

记不住就存这句

    帮我按条件筛一批股票，先看看有哪些条件可选
```

"先圈定范围再排序"这条最容易埋。文档里写了，没人读到那一节。

三张卡的原文都在 [`examples/`](examples/)。

## 卡片长什么样

去掉装饰符号，只留结构。四段，可以少，不能凑：

```
<✅ 可用 ｜ ⚠️ 部分可用，原因 ｜ ❌ 没能验证，原因>
<一句话：它是什么，强在哪，弱在哪>

能干什么
    动作        会得到什么
    动作        会得到什么

几个多半不知道的
    口令        为什么值得知道
    口令        为什么值得知道

记不住就存这句
    最短的那一句
```

第二种标题按性质选：工具类写「能干什么」，方法 / 准则类写「什么时候用得上」。

两个以上的 skill 会合并成一张族卡，第二种标题换成「你想做什么」，按你会说出口的话分组，不按命令名或模块名。

卡里不出现文件路径、文件名、来源。你要的是能干什么，不是它在哪。

格式细节和更多样例在 [`example.md`](example.md)。

## 和 skill-creator 是一对

```
skill-creator      建 skill、改 skill
skill-onboarding   建完之后跑一遍，验证第一次运行，给一张卡
```

建，跑，出卡，然后拿卡上暴露的问题回去改 skill。缺依赖、文档和实现对不上、能力没写清楚，都是这一轮该修的。

默认开着协同。用 skill-creator 建完或者改完一个 skill，接着跑一遍这个，别建完就走。

分工也简单：建改删归 skill-creator，跑和出卡归这里，质量打分两边都不做。

## 安装

```bash
git clone https://github.com/yuzhang-zhong/skill-onboarding.git \
  ~/.workbuddy/skills/skill-onboarding
```

换成你自己的 skills 目录就行，Claude Code 用 `~/.claude/skills/`。状态脚本只用 Python 标准库，不用装东西。

## 配置

```bash
python scripts/onboarding_state.py config                # 查看
python scripts/onboarding_state.py config set <key> <v>  # 修改
python scripts/onboarding_state.py config reset          # 恢复默认
```

| 键 | 默认 | 作用 |
|---|---|---|
| `language` | `zh` | 卡片语言，`zh` / `en` / `auto` |
| `auto_trigger` | `true` | 首跑后是否自动补卡 |
| `max_lines` | `40` | 单卡行数上限 |
| `family_max_lines` | `60` | 族卡行数上限 |
| `exclude` | `[]` | 不引导的 skill |
| `pair_with_skill_creator` | `true` | 建完改完 skill 后自动补一次验证 |

填错的值当场拒绝，实在乱了 `config reset` 回到默认，写不坏。

## 谁该用它

| | 面向 | 产出 |
|---|---|---|
| `skill-creator` | 作者 | 新建、迭代 skill |
| `skill-tester` 一类 | 作者 | 结构校验、质量分级 |
| **本 skill** | **使用者** | **首次使用后的用法卡** |

判断一个 skill 好不好用是别人的事。这里只管你该怎么用它。
