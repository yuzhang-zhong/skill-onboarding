## 装了一堆 skill，常用的就那一个

skill 不会一次全读进来。会话刚开始，只有名字和一句描述进到上下文里，正文要等真正用上才读。所以一个 skill 就算写了八个功能，你也只会碰上最前面两个，另外六个一直藏着。

这个 skill 就补这一个缺口。你第一次真正用上某个 skill 之后，它会跑一遍真实验证，把全文读完，给你一张卡，上面写的是你没发现的那部分。

## 三步

1. **定对象** 一个 skill，还是一组
2. **探测** 读全文，跑只读探针。真跑，不猜
3. **出卡** 一张能一口气读完的卡

## 一组 skill，其实是同一件事

飞书那 21 个技能，底层是一个命令。设计那 7 个，是一个东西的不同部位。

一个一个出卡没意义。你只会收到 21 张碎片，照样拼不出全貌。所以合并成一张。

顺便算个差集：工具本身支持的，减去你本地已经装的。差出来的部分，就是你完全不知道的。

## 三个真实案例

下面三张卡是实际跑出来的，不是示意。原文照贴。

### 一、你有 21 个飞书技能

要做个表格，在 `lark-sheets`、`lark-base`、`lark-drive` 之间来回猜。想发消息，不确定该找 `lark-im` 还是 `lark-unified`。21 个名字都见过，从没搞清谁管谁。

跑一遍，拿到这个：

```
✅ 可用。CLI 本体正常，自检全部通过。两处要留意，内置说明文档比主程序落后一个版本，当前生效的应用身份和配置里指定的那个对不上。

飞书全家桶。26 个业务域，你本地那 21 个飞书技能，底层都是它一个。

能干什么

    聊消息、管群      发消息、搜聊天记录、拉群、加成员、置顶、电话短信加急
    写文档           建文档、读内容、插图插文件、搜文档、回滚版本
    做表格           读写单元格、公式校验、图表、透视表、条件格式、导入导出
    管云盘           上传下载、复制移动、评论、协作权限、文件夹双向同步
    排日程、开会      看日程、查忙闲、找会议室、推荐时间、回复邀请、转移组织者
    记待办           建任务、标完成、提醒、清单、搜索、传附件
    其余             知识库、幻灯片、画板、审批、考勤、OKR、邮箱都有

几个多半不知道的

    先预览一下，别真发        所有操作都支持预演模式，发消息、改文档前能先看结果
    你自查一下飞书有没有问题    一条命令做全身体检，版本、授权、身份、网络，出问题直接定位
    这周的日程和待办一起给我    现成的组合用法，一句话出当天或本周摘要
    Markdown 发成飞书文档     完整流水线，导入、传图、把图挪到对应标题下、加图注
    本地这个文件夹同步上去      目录级镜像和双向同步，不用一个个手动传
    表格里加透视表和条件格式    表格域比想的深，透视表、条件格式、迷你图、历史回退都能做

记不住就存这句

    飞书那边帮我……，先预览一遍
```

一句话就够：21 个技能，1 个工具。

### 二、你装过一个去 AI 味的工具，然后忘了

你记得它能挑出"仿佛""一丝""缓缓"这类词。别的呢？想不起来了。什么时候装的、为什么后来没用，也记不清。

跑一遍，拿到这个：

```
⚠️ 部分可用。核心扫描脚本实测正常，但该技能处于停用状态，不会自动触发，文档提到的配套排版步骤也没随包装上。

中文写作的去 AI 味工具。检测、分级、改写都有。强项是规则库，几百条禁用词加六套大师手法，弱项是自动化，多数改动得人来判断。

能干什么

    扫一下这几章的 AI 味     出量化报告，禁用词密度、排比段数、心理词占比，自动给轻中重分级
    把这段改得不像 AI 写的   按三遍流程走，去泛化词、去书面腔、回自然感
    我说不出哪不对          走深层描写层，指出是情绪宣告还是心理直陈，给大师级改法

几个多半不知道的

    按余华的路子改这段      内置六套可以点名指定的手法，视觉代替心理、动作外化情绪、白描胜形容词、环境烘托、用缺席写存在、动作带话
    哪些能自动改哪些不能    标点连用、时间定格超量、轻动作堆叠、踩雷词能自动修，语境敏感的句式只报告不自动改，避免误伤
    怎么让它真正能用起来    去技能管理里启用，之后才会被自动调用。另外跑完自动修复建议自己通读一遍

记不住就存这句

    扫一下这段的 AI 味，重的直接改
```

第一行就说实话：这技能是停用状态，得先启用才会自动触发。

### 三、你想做个 PPT，不知道找谁

`slides`、`design`、`design-system`、`ui-ux-pro-max`，四个都沾边。你随手挑了 `slides`，做了个能看的版本，没再想别的。

跑一遍，拿到这个：

```
✅ 可用。内置的检索库实测通过，风格库、配色库、行业库都能真实查出结果。生成类功能需要外部服务的密钥，本次未实测。

一整套设计生产线。品牌基调、配色字体、Logo、名片、PPT、banner、社媒图都在里面。你有 7 个看起来很像的设计技能，其实是一个东西的不同部位。

能干什么

    定品牌调性、视觉规范    brand
    定颜色字号间距的体系    design-system
    写前端界面             ui-styling
    界面美学把关           高品质前端设计
    生成整套设计系统        ui-ux-pro-max，12 个域 × 21 种技术栈
    做 Logo、图标、banner   design 内置
    做整套企业视觉          design 内置，50 种物料
    做 PPT、提案            design 内置，带图表

几个多半不知道的

    帮我查下咖啡店用什么配色    内置可检索的行业库，给配色、字体、图形符号，还说要避开什么
    先给我一份设计简报         一句话生成完整简报，风格方向、配色、字体、行业惯例
    这个风格适合什么行业       每个风格都标了适用与避用范围，选之前先看合不合适
    整套企业视觉一起做         现成的一条龙，一次出 50 种物料，不用逐个提
    风格想要更大胆一点         可以调三个旋钮，视觉变化度、动效强度、视觉密度，各 1-10 档

记不住就存这句

    按我的品牌做一套视觉，先给我设计简报
```

七个设计技能，一张表理清。最后那条旋钮，你原本猜不到。

三张卡的原文都在 [`examples/`](examples/)。

## 卡片长什么样

去掉装饰符号，只留结构：

```
<✅ 可用 ｜ ⚠️ 部分可用，原因 ｜ ❌ 没能验证，原因>
<一句话，它擅长什么、不擅长什么>

能干什么
    动作        会得到什么
    动作        会得到什么

几个多半不知道的
    口令        为什么值得知道
    口令        为什么值得知道

记不住就存这句
    最短的那一句
```

两个以上的 skill 会合并成一张族卡，第二个小标题换成"你想做什么"，按你会说出口的话分组。

卡里不出现文件路径、文件名、来源。你要的是能干什么，不是它在哪。

格式细节和更多样例在 [`example.md`](example.md)。

## 和 skill-creator 是一对

```
skill-creator      建 skill、改 skill
skill-onboarding   建完之后跑一遍，验证第一次运行，给一张卡
```

建，跑，出卡，然后拿卡上暴露的问题回去改 skill。缺依赖、文档和实现对不上、能力没写清楚，都是这一轮该修的。

默认开着协同。用 skill-creator 建完或者改完一个 skill，接着跑一遍这个，别建完就走。

分工也简单：建改删归 skill-creator，跑和出卡归这里，质量打分两边都不做。

## 安装

```bash
git clone https://github.com/yuzhang-zhong/skill-onboarding.git \
  ~/.workbuddy/skills/skill-onboarding
```

换成你自己的 skills 目录就行，Claude Code 用 `~/.claude/skills/`。状态脚本只用 Python 标准库，不用装东西。

## 配置

```bash
python scripts/onboarding_state.py config                # 查看
python scripts/onboarding_state.py config set <key> <v>  # 修改
python scripts/onboarding_state.py config reset          # 恢复默认
```

| 键 | 默认 | 作用 |
|---|---|---|
| `language` | `zh` | 卡片语言，`zh` / `en` / `auto` |
| `auto_trigger` | `true` | 首跑后是否自动补卡 |
| `max_lines` | `40` | 单卡行数上限 |
| `family_max_lines` | `60` | 族卡行数上限 |
| `exclude` | `[]` | 不引导的 skill |
| `pair_with_skill_creator` | `true` | 建完改完 skill 后自动补一次验证 |

填错的值当场拒绝，实在乱了 `config reset` 回到默认，写不坏。

## 谁该用它

| | 面向 | 产出 |
|---|---|---|
| `skill-creator` | 作者 | 新建、迭代 skill |
| `skill-tester` 一类 | 作者 | 结构校验、质量分级 |
| **本 skill** | **使用者** | **首次使用后的用法卡** |

判断一个 skill 好不好用是别人的事。这里只管你该怎么用它。
